# 上下文管理面板 · 产品重设计

> 状态：**已定稿（2026-11-13 拍板），待落地**
> 拍板结论：① 模型侧静默，不加能力脚注 ② 工具级开关必做 ③ 不做"新会话默认" ④ 引入 tiktoken
> 前作：`docs/design/session-tool-policy-design.md`（2026-11-12 拍板：黑名单制 / 只裁 MCP + 非内置 skill / 入口在输入框）——这三条不变，本稿只重做"面板是什么"。

## 1. 为什么现在"不合理"

### 1.1 概念错位：叫上下文管理，却没有上下文

面板里只有 MCP 服务器开关，没有任何"当前上下文占了多少、被什么占满"的信息。用户真正的疑问是「我这轮 10 万 token 花在哪了」，面板回答的是「你要不要关掉钉钉文档」。

实测（2026-11-13，本机）：

| 项 | 真实值 |
|---|---|
| 已连接并注入的 MCP 服务器 | 4 台 |
| 注入工具总数 | **156 个**（钉钉文档 40 + 火山搜索 1 + Zhishui-mcp 33 + zhishui-requirement 82） |
| 这些工具的**描述文本** | **38.1k 字符**（还没算参数 schema） |
| 本会话最近一次对话请求 prompt | **103,537 token** |
| 面板底部显示 | **「每轮约省 ↑0.0k」** |

工具 schema 很可能占这一轮 prompt 的 1/4～1/3，面板却告诉用户"省 0.0k"。这是最刺眼的不合理。

### 1.2 数字没有基准，也没有可信度

- `TOK_PER_TOOL = 330` 是前端硬编码常量，40 工具和 1 工具一个价。
- 只统计"被关掉的 server"，默认全开时必然显示 0.0k——**默认态就是最没有信息量的态**。
- 未连接/全局停用的 server 工具数为 0，关掉它们"省 0"，进一步污染数字。
- 单位说"每轮"，实际一个 turn 可能调用模型多次，schema 每次都重复注入。

### 1.3 四种状态被压成一个"灰"

现状只有 `tools === 0` 就置灰（opacity 45%），于是下面四件事长得一模一样：

| 真实状态 | 现状表现 | 用户以为 |
|---|---|---|
| 本会话被用户关掉 | 灰 | 关了 |
| 设置里全局停用（`enabled=false`） | 灰 | 关了 / 坏了 |
| 连接失败（如 `MCP_KEY_EXPIRED`） | 灰，无错误文案 | 关了 / 坏了 |
| 已连接但确实 0 工具 | 灰 | 关了 |

截图里钉钉待办/日历/AI 表格是"设置里停用"，钉钉AI听记是"连接失败（key 过期）"——后者需要用户去修，但面板完全没提示，也没有重试入口。

### 1.4 粒度太粗

一个 40 工具、一个 82 工具的 server 只有一个总开关。设置页早就有 per-tool `disabled_tools`，会话层却只能整组砍。用户想"钉钉文档只留读、不留下发"时无路可走。

### 1.5 列表装不下

`w-80`（320px）+ `max-h-64`（256px，约 8 行）。当前 8 台 server + 41 个 skill，skills 段永远在折叠线以下——用户根本不知道还有技能可以关。没有搜索、没有分组折叠、没有"已关 N 项"摘要。

### 1.6 文案与生效态

- 「勾掉 = 本会话不注入（省上下文）」——实际语义是"模型看不到也不能调用这些工具"，不是"不注入上下文"。
- 「下一轮生效」是静态装饰，改完没有任何 pending 反馈；turn 运行中改是什么行为也没说。
- 底部「每轮约省 ↑0.0k」：向上箭头 + "省"，方向和语义相互打架。
- 自动保存（400ms 防抖）与底部「完成」按钮是两条保存路径，`saved` 只长在按钮上。

### 1.7 模型侧行为不可预期

工具被关后直接从 schema 消失，模型不知道自己"被禁用了能力"：要么答"我没有这个能力"，要么编一个相近工具名。skill 的报错文案写「输入框 → 上下文管理 可重新开启」，但被禁 skill 已不在索引里，模型根本不会去调——这条兜底文案基本失效。

### 1.8 只能按会话设

每个新会话都要重设一遍；没有"设为新会话默认"。同时入口是一个纯图标，关过东西后也没有任何标记，用户过两天会忘记自己关过钉钉，然后报"模型不会用钉钉"。

## 2. 设计目标

**让用户在 3 秒内回答两个问题：**

1. 这一轮上下文被什么占满了？
2. 关掉哪个能省多少、我会失去什么？

原则：

1. **先给账本，再给开关**（budget-first，不是 switch-first）。
2. **数字必须有基准**：显示"当前注入量"和"关闭后的 delta"，而不是孤零零的"省"。
3. **状态必须可分**：已连接 / 本会话关闭 / 设置停用 / 连接失败，四种视觉与文案。
4. **关闭可逆；模型侧静默**（2026-11-13 拍板），后果由面板文案说清楚，不额外注入脚注。
5. **尊重既有拍板**：不做预设档，不做 builtin，不重建设置页。

## 3. 目标形态

面板 420px 宽、最高 70vh，分三段：预算头 / 能力列表 / 状态栏。

### 3.1 默认态

```
┌─ 上下文 ─────────────────────── 每次请求 ≈103.5k ─┐
│  ████████████████████░░░░░░░  103.5k / 128k  [压缩]│
│  历史 71.2k · 工具 ≥27.9k · 技能 1.4k · 系统 3.0k ▾│
├───────────────────────────────────────────────────┤
│  工具与能力                            🔍 [搜索]   │
│  ● 钉钉文档             40 工具  ≈9.8k    [开]     │
│  ● zhishui-requirement  82 工具  ≈10.6k   [开]     │
│  ● Zhishui-mcp          33 工具  ≈4.2k    [开]     │
│  ● 火山引擎联网搜索       1 工具  ≈0.2k    [开]     │
│  ⚠ 钉钉AI听记     连接失败 MCP_KEY_EXPIRED  重试   │
│  ⊘ 设置中已停用 3 项（待办、日历、AI 表格）    ▸   │
│                                                   │
│  技能 41 · 已关 0                            ▸    │
├───────────────────────────────────────────────────┤
│  已关闭 0 项 · 无变化                     [完成]   │
└───────────────────────────────────────────────────┘
```

### 3.2 关掉一个 server 后（即时预览，未保存前就反馈）

```
│  ○ 钉钉文档             40 工具  -9.8k    [关]     │
│  ██████████████░░░░░░░░░  预览 93.7k / 128k        │
├───────────────────────────────────────────────────┤
│  已关闭 1 项 · 每次请求 -9.8k (-9.5%)     [完成]   │
```

- 预算条出现斜纹预览段，立刻看到"关掉之后会到哪"。
- 底部数字从"省"改成**带符号的 delta + 占比**。
- 未连接的行不显示金额（显示 `—`），因为关掉它本来就不省。

### 3.3 展开组成明细

```
│  组成明细（≈，按上次请求实测校准）                 │
│  对话历史            71.2k  69%          [压缩]    │
│  钉钉文档             9.8k   9%          [关闭]    │
│  zhishui-requirement 10.6k  10%          [关闭]    │
│  Zhishui-mcp          4.2k   4%          [关闭]    │
│  火山联网搜索          0.2k   0%          [关闭]    │
│  技能索引             1.4k   1%          [管理]    │
│  系统提示与记忆        3.0k   3%                   │
│  其他/未归类          2.1k   2%                    │
```

数字全部标 `≈`；悬停显示口径："固定项按实际注入文本估算，历史 = 上次请求实测 − 固定项"。

## 4. 关键交互规则

### 4.1 四态状态机

| 数据状态 | 行样式 | 开关 | 右侧 |
|---|---|---|---|
| `enabled` + `connected` + 本会话启用 | 正常 | 开 | `N 工具 · ≈x k` |
| `enabled` + `connected` + 本会话关闭 | 名称淡化 + "本会话已关闭" | 关 | `-x k` |
| `enabled` + `connected=false` | 琥珀警示 + 错误摘要 | 开（可关，但不省） | `连接失败 · 重试` |
| `enabled=false`（全局停用） | 收进折叠组 | 无 | `去设置` |

- "设置中已停用"默认收起一行摘要，不再占用列表主区。
- 连接失败的 server 提供行内「重试」，直接打 `POST /api/mcp/reconnect?server=`。
- 0 工具的已连接 server 单独标 `0 工具`，不置灰。

### 4.2 计数与 delta

- 打开面板时显示 **当前每次请求总量** 和 **工具小计**。
- 每次切换：`-x k` 即时出现，footer 累计 `已关闭 N 项 · 每次请求 -x k (-y%)`。
- 单位统一为"**每次请求**"，tooltip 补一句"本会话每轮约 N 次模型调用"。
- 恢复全开时 footer 显示"无变化"，不显示 0.0k。

### 4.3 列表能力

- 搜索：server 名、工具名、skill 名、skill 描述全文过滤；`⌘F` 聚焦。
- 技能区默认折叠，标题带 `技能 41 · 已关 3`；展开后每行两行：名称 + 一句话描述（当前只有名字，无法判断是什么）。
- 分区标题 sticky；列表内滚动，footer 固定。
- 关闭项置顶？**不**。保持稳定顺序，避免切换时行跳动；用顶部"已关闭 N 项"摘要定位。

### 4.4 工具级开关（必做，2026-11-13 拍板：不能只到 server 级）

- 点 server 行左侧 chevron 展开工具清单，支持搜索；每项一个开关。
- server 开关变三态：全开 / 部分（`12/40`）/ 全关。
- 数据模型新增 `tool_policy.mcp_tools_disabled: {server: [full_name]}`；存 `toolDetails[].fullName`（graph 面向的 ASCII 名，运行时可直接与 langchain 工具名比对，避免再走一次 slug 映射）；过滤时先按 server 前缀、再按全名精确剔除，只接受 `mcp_*`（builtin 永不可隐藏）。
- 工具清单懒加载：展开某个 server 时才打 `GET /api/mcp?tools=1` 取 `toolDetails`，不随面板首屏拉 156 个工具的详情。
- 与设置页的 `disabled_tools` 关系：设置页是**全局**默认，会话策略是**本会话叠加**；两层都关才算关。UI 上标注"设置中已禁用"的工具为只读行。
- 继承：subagent/worker/delegation 复制父会话的 `mcp_tools_disabled`（与现有 server 黑名单同一继承路径）。

### 4.5 保存与生效

- 保留 400ms 防抖自动保存；底部按钮改为纯「关闭」，不再承担保存语义。
- 右上角状态徽标：
  - 刚打开：`改动自动保存`
  - 改动后 2s：`已保存 · 下一轮生效`
  - turn 运行中：`本轮结束后生效`
  - 失败：红色 `保存失败 · 重试`，开关回弹到服务端状态（乐观更新要能回滚）。
- 关闭面板时 flush 待存（现状已有），但不再依赖"用户点完成"。

### 4.6 模型侧：静默（2026-11-13 拍板）

- 关闭后 schema 不注入，**不追加任何能力脚注**。
- 代价（已接受）：模型不知道自己被禁用，可能答“我没有这个能力”，也可能编相近的工具名。
- 缓解放在面板文案，不放在 prompt：
  - 行内：`本会话已关闭 · 模型当前不可用`
  - 关闭时 footer 提示：`关闭后模型将看不到这些工具，需要时随时开回`
- 不新增 system prompt 注入，避免脚注本身计费/被模型当作指令。

### 4.7 作用域：仅本会话（2026-11-13 拍板：不做默认）

- 所有开关只写 `session.meta.tool_policy`，不写全局 settings。
- 不提供“新会话默认使用这套设置”；新会话一律从全开开始。
- 入口图标在有裁剪时带小圆点；tooltip `上下文 · 已关闭 3 项`，避免用户遗忘（这只是提醒，不是作用域）。

## 5. 数据与计量

### 5.1 新接口

`GET /api/sessions/{id}/context_breakdown`

```jsonc
{
  "used": 103537,            // 最近一次对话请求 prompt_tokens（last_chat_input_tokens）
  "window": 128000,          // context_window_for
  "threshold": 96000,        // min(compact_threshold_tokens, window*0.75) —— compaction.py 同一函数
  "estimated": true,
  "parts": [
    {"key":"history","label":"对话历史","tokens":71200,"kind":"history","action":"compact"},
    {"key":"tools:钉钉文档","label":"钉钉文档","tokens":9800,"kind":"mcp","server":"钉钉文档","tools":40,"enabled":true},
    {"key":"skills","label":"技能索引","tokens":1400,"kind":"skills","count":41,"disabled":0},
    {"key":"system","label":"系统提示与记忆","tokens":3000,"kind":"system"}
  ],
  "policy": {"mcp_disabled":[],"skills_disabled":[]}
}
```

### 5.2 计数：tiktoken（2026-11-13 拍板）

- 运行时新增 `tiktoken`，统一用 `o200k_base`（中文覆盖优于 cl100k）。
- **离线是硬约束**：tiktoken 默认从 openaipublic 下载 BPE，桌面版必须随包内置：
  - `pyproject.toml` 加依赖；`ginno-runtime.spec` 用 `collect_all("tiktoken")` 收 Rust 扩展；
  - 把 `o200k_base.tiktoken` 放进 bundle，启动时设 `TIKTOKEN_CACHE_DIR` 指向该目录；
  - 加载失败（缺文件/不支持平台）自动降级到字符估算（CJK×1.0 + 其余÷3.6），面板标「估算」且不报错。
- 体积（实测）：wheel 1.04MB（cp311 macos arm64）+ `o200k_base` 3.61MB ≈ **4.7MB**；当前 `Ginno.app` 226MB，增幅 <3%，PyInstaller 解包后总增量 <10MB。
- 口径：固定项按 tiktoken 精确计数；provider（Claude/Qwen/DeepSeek）tokenizer 不同，仍需用最近一次 `prompt_tokens ÷ 固定项计数` 校准，clamp 到 `[0.85, 1.15]`；历史 = `used − 固定项`（≥0），保证分项和等于实测。
- 性能：156 个工具 schema 一次性编码约几十 ms；按 `(policy_version, mcp_config_mtime, 工具清单 hash, locale)` 缓存，打开面板目标 <300ms。

### 5.3 边界

- 新会话、还没跑过 turn：`used = 固定项`，预算条标“首轮预计”。
- 窗口未知（`context_window=0`）：按 200k 兜底，并显式标“窗口未知，按 200k 估算”。
- 压缩后：`used` 取压缩后下一次真实调用，避免锯齿（沿用 `NON_CONTEXT_SOURCES` 过滤）。
- 子会话：继承父 policy（已有，含 `mcp_tools_disabled`）；面板只显示当前会话自己的开关，不展示继承来源（P2 可加一行“继承自父会话”）。

## 6. 分期

| 期 | 内容 | 量 |
|---|---|---|
| **P0** | tiktoken + breakdown 接口 + 预算头 + 四态 + delta footer + 搜索 + 技能折叠 + **工具级开关（数据模型/过滤/懒加载/三态）** + 文案与保存态修正 | ~1.5 天 |
| **P1** | 组成明细展开 + 失败重试入口 + 入口圆点 + 阈值着色 | ~0.5–1 天 |
| **P2** | 自动建议（30 天未用/接近阈值）+ 会话列表 `⊘N` 角标 + 压缩入口 | ~0.5 天 |

P0 一次消掉“0.0k / 一片灰 / 不知上下文多少 / 40 工具只能整组”四个最刺眼的问题。

## 7. 验收标准

1. 默认态不再出现 `0.0k`；显示当前每次请求总量与工具小计。
2. 关闭一个 40 工具 server，footer 出现 `-x k (-y%)`，预算条同步预览。
3. 保存后下一轮真实 `prompt_tokens` 的下降与预估误差 ≤ ±15%（tiktoken + 校准口径）。
4. 工具级：关掉 server 下某个工具后，行内显示 `39/40`，server 开关呈“部分”；下一轮该工具不再出现在工具列表。
5. 8 台 server 的四种状态全部正确呈现；失败项有错误摘要 + 重试可用。
6. 搜索“日历”能命中；无结果有空态；技能区不需要滚过折叠线才能发现。
7. 关闭后重启面板勾选保持（786db20 / 2e4a82c 回归）。
8. turn 运行中修改显示“本轮结束后生效”；保存失败时开关回弹。
9. 离线冷启动：tiktoken 从 bundle 加载成功；删掉 vocab 时降级为字符估算且面板不报错。
10. bundle 增量 <10MB；中英文案同步；420px 面板在 768px 窗口下不溢出。

## 8. 拍板结论（2026-11-13）

| 议题 | 结论 |
|---|---|
| 模型侧能力脚注 | **不做**，静默；后果由面板文案承担 |
| 工具级开关 | **必做**，进 P0（不仅 server 级） |
| 新会话默认作用域 | **不做**，仅本会话 |
| tiktoken | **引入** `o200k_base` + 随包内置；体积 <5%，仍需实测校准 |

## 9. 不做

- 不做“全部 / 最小 / 自定义”预设档（2026-11-12 已拍板）。
- 不做模型侧能力脚注（2026-11-13 拍板：静默）。
- 不做“新会话默认”作用域（2026-11-13 拍板）。
- 不把 builtin 工具与内置 skill 纳入开关。
- 不做逐 turn 手工挑选上下文（每轮弹窗选文件/记忆，摩擦过高）。
- 不在本面板编辑 MCP 连接配置（跳设置）。
- 不做消息级编辑/回溯——那属于会话时间线，不是上下文裁剪。
- 不承诺精确 token 计费，所有数字标 `≈`。
