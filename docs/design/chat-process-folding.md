# 聊天执行过程自动折叠

目标是让长任务像 ChatGPT 的 Codex 模式一样容易扫读。默认视图保留当前在做什么、给用户的说明和最终交付。需要排查时，展开对应执行过程，按发生顺序回看思考摘要、工具结果和 Diff。

## 聊天里的样子

```text
▶ 已完成 12 项操作 · 读取 5 · 修改 2 · 命令 5

已整理完需求清单，接下来校验 HTML 和验收映射。

◉ 正在执行 · 校验 HTML                        已完成 3 项  ›
```

任务完成后，运行行原位变成「已完成」行，下面直接接正文或产物。折叠行与现有工具标题同高，使用现有的紫色、琥珀色和中性色区分思考、等待与已完成。标题优先显示安全且简短的动作描述，如「读取 AgentMapper.xml」或「执行命令」。长路径、脚本和输出在展开后查看。计数从真实工具记录计算，每次调用计一次。思考摘要按模型请求保留，摘要段数在原卡内显示。

## 分组和自动折叠

| 场景 | 默认呈现 |
| --- | --- |
| 连续执行 | 在同一助手回复中，把相邻的普通工具、思考摘要和旧版思考块放进一组。跨模型请求可继续同组，展开后按请求和工具原顺序浏览。 |
| 运行中 | 连续过程只占一个入口，显示最新动作和已完成数。多个工具并行时显示「正在执行 N 项」，避免在每个工具输出片段到达时切换标题。第一项运行中即可显示这个入口。 |
| 结束的短过程 | 单个简单工具或单张思考卡沿用当前显示。连续过程已包含三个过程块或有两次工具调用时，完成后保留一行摘要。进入组展示后，组头保持同一个位置。 |
| 正文和交付物 | 正文、文件、图片、引用、交互组件各自留在原位。正文中的进度说明也为执行过程划界，前后各成一组。 |
| 待操作或失败 | 权限请求、提问、浏览器接管、交互式 MCP、后台任务和失败记录保留独立可见入口。普通工具失败会显示失败标题及原因摘要，用户可展开原始错误。断线、停止和取消有各自状态，完成计数来自已确认回执。 |

工具失败使用已有的明确失败信号，普通输出中的单词 `error` 不作为判断依据。预写产物的工具记录可折叠，实际交付的文件卡继续在原位展示。

## 展开后的行为

- 点击组头展开，保留现有思考卡、工具行和 Diff。组内的小卡可分别展开，用户能直接定位到一次具体请求或编辑。
- 用户手动展开的组在本次浏览中保持打开，后续回执、下一组开始和回合结束都尊重该选择。可点击同一个组头收回。
- 跟随最新时，让新动作和最终答复继续进入视口。用户往上读时，保持正在看的内容和滚动位置；当前可见的旧过程在用户离开后再自动收拢。手动展开或折叠时保持组头位置。
- 对话搜索和跳转到某条记录时，先展开命中所在的组，再定位原记录。刷新或重连后按同一套规则回放分组，恢复原有事件顺序。键盘展开、折叠使用按钮的 `aria-expanded`，减弱动态效果设置下使用静态状态图标。

## 实现与验收范围

在聊天渲染层对现有块序列分组，共用同一规则处理流式输出和历史回放。正文、引用、原始消息和工具数据保持原序。当前的折叠组件继续负责各自的内容，外层负责是否展开整段。组标识由回合标识和首个过程块确定，避免流更新、收尾或断线补帧时换壳。

1. 复刻截图中的长链路，连续十余条内部记录在完成后只占一行。展开可以逐项查看摘要、命令和 Diff。
2. 运行中一直能看见正在处理的动作。滚到上方阅读、手动展开或折叠，都能维持阅读位置。
3. 中间出现提问、权限等待、工具失败或交付文件时，对应入口仍可见。并行工具和断线恢复时，摘要计数和最终状态一致。
4. 历史刷新后得到相同的分组和顺序。搜索命中折叠组内的记录仍可定位。
