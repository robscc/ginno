# 模型标签与切换兼容

**状态**：方案稿

## 目标

用户可以在「设置 → 模型 API」为具体模型单选「默认」或「Codex」。新模型和升级后的存量模型初始选「默认」。同一模型 ID 在不同 API 配置下可以分别选择。

「默认」提供低、中、高三个思考档位，使用已保存的 API 配置。「Codex」启用扩展档位、专用请求参数和切换时的兼容策略。模型名称和网关目录用于推荐，保存后的选择决定实际行为。

## 设置页交互

沿用「编辑 API 配置 → 模型列表」。从左到右是默认模型单选、模型名、标签按钮和原有的「×」。标签按钮采用与聊天模型按钮相同的外观，展开后在「默认」和「Codex」之间单选。有可靠依据时，在菜单内的 Codex 项右侧显示「推荐」。选中 Codex 后，可展开该行的「Codex 参数」调整档位上限并查看适用字段。

| 模型 | 初始选择 | 选择 Codex 时的推荐上限 |
| --- | --- | --- |
| `codex/gpt-6.2-astra`、`codex/gpt-6.2-sol` | 默认 | `ultra` |
| `codex/gpt-5.3-codex` | 默认 | `xhigh` |
| `codex/新别名` | 默认 | 待确认 |
| `chatgpt-api/gpt-6.2-astra`、`deepseek-v4.1-flash` | 默认 | 手动选择 |

标签选择和移除模型都先更新表单草稿，统一点「验证并保存」后生效。移除默认模型时，由剩余列表的第一项接替。手动添加和从 API 拉取的模型使用相同的推荐规则。

聊天沿用现有输入框、模型按钮和档位角标。点模型行切换，点行尾箭头展开思考强度。默认标签提供低、中、高三档。Codex 在此基础上按配置上限依次显示「极高」(`xhigh`)、「最大」(`max`) 和「Ultra」(`ultra`)。「自动」跟随服务商配置，上限待确认时可先选自动。

## Codex 请求参数

「Codex 参数」随 API 协议显示适用字段。Anthropic 可在行内按网关要求选择字段。下表是请求构造规则，聊天中实际选的档位决定字段值。

| 实际请求协议 | 档位字段 | 兼容规则 |
| --- | --- | --- |
| OpenAI Responses | `reasoning.effort` | 省略 `temperature` |
| Chat Completions | `reasoning_effort` | 省略 `temperature`、`enable_thinking` 和 `enable_search` |
| Anthropic | SDK 序列化为 `output_config.effort`，明确要求顶层字段的网关使用 `reasoning_effort` | 两种档位写法二选一，省略 `thinking.budget_tokens` |

选择默认后使用目标模型原有的协议参数规则。Anthropic 的网关格式需按实际接入契约验证。

## 前端推荐规则

1. **优先读取模型目录中的明确能力声明。** 当网关给出模型系列及支持档位，推荐相应标签与上限。目录只给模型 ID 时继续使用后两条。
2. **按明确的 Codex 路由或型号推荐。** `codex/` 路由可以推荐 Codex。已核实的明确型号可以附带上限。本机 Codex CLI 0.170.0 的目录显示 Astra 和 Sol 支持 `ultra`，Luna 到 `max`。5.2 和 5.3 Codex 仍推荐到 `xhigh`。仅能确认路由时，推荐标签并将上限留为待确认。
3. **遇到相同后缀或无可靠信号时保留手动入口。** 其他网关池里出现相同的型号后缀，可能使用不同的能力或映射。只看见 `gpt` 或同名后缀时，标签保持「默认」，用户可自行选择。

推荐始终是待采纳项。它可以随目录更新和模型别名变化重新计算，已保存的标签与上限由用户编辑。打开已有配置时，旧版靠名称识别的模型也能看到对应推荐。

## 从 Codex 切到其他模型

当前请求按它开始时的模型执行。切换生效后的下一次模型请求，使用目标 API 配置、模型和标签重新选择参数并整理发往上游的消息。

| 内容 | 下一次请求的处理 |
| --- | --- |
| 思考强度 | 从 Codex 切到「默认」模型时，继承的档位回到「自动」，包括 `high`。若用户在切换时明确选了目标模型的合法档位，按新选择执行。两个 Codex 模型之间可沿用双方支持的档位，超过目标上限时回到「自动」。 |
| 请求参数 | 由目标模型和目标协议重新构造。`reasoning.effort`、`output_config.effort` 和续传引用等字段按目标规则生成。 |
| 聊天正文和工具记录 | 复制可携带的用户消息、回答正文和成对的工具调用及结果，转换为目标协议格式。 |
| 协议专用历史 | 仅在来源和目标兼容时附带。跨模型或跨端点时，过滤源模型专用的摘要块、加密思考、签名、响应和输出项引用，以及目标协议无法表示的服务端工具项。目标模型若需要自己的推理字段，按自身契约提供。 |

过滤发生在发往模型的临时副本上。档位因切换回到「自动」时，模型菜单同步角标，并沿用会话通知显示一次「思考强度已恢复为自动」。

## 落地与验收

- 设置保存以 `API 配置 ID + 模型 ID` 定位标签和可选上限。推荐结果单独计算。模型菜单、档位校验和请求构造统一读取已保存能力。
- 选择「默认」时，`codex/gpt-6.2-astra` 使用通用规则和三个可选档位。选择「Codex」并保存 `ultra` 上限后，菜单提供 `xhigh`、`max` 和 `ultra`，刷新和重启后仍保留。相同 ID 在另一份 API 配置中可保持「默认」。
- 用一个型号名中没有 `codex` 的模型验证手动打标也能启用同一套行为。用新别名验证推荐不会擅自填入未经确认的上限。
- 在同一会话先用 Codex 生成摘要和工具记录，再切换到普通模型。验证新请求移除了源模型专用字段，工具调用和结果依然配对，聊天历史仍可查看。覆盖同一端点换模型、跨端点和跨协议切换。
- 复用现有 API 配置表单和聊天模型菜单。保存时的连接探针验证当前配置可用，另用目标协议的真实 SDK 请求体对照切换结果。

交互原型中的 Astra 和 Sol 已预设 Codex 标签和 `ultra` 上限。在聊天模型菜单中展开任一模型，即可试用三个扩展档位。
