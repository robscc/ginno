# 模型标签与切换兼容

**状态**：方案稿

## 目标

用户可以在「设置 → 模型 API」给具体模型打标签，决定 Ginno 对该模型启用的特殊行为。新模型和升级后的存量模型初始标签都为空。同一模型 ID 在不同 API 配置下可以分别打标。

首期提供 `Codex` 标签，统一控制扩展思考档、协议参数映射和切换时的兼容策略。未打标签的模型按通用规则和已保存的 API 配置工作。模型名称和网关目录用于推荐，用户保存的标签是能力开关。

## 设置页交互

沿用现有「编辑 API 配置 → 模型列表」。每行显示模型名、标签入口和现有的默认模型与移除操作。已打标的模型显示可点开的紫色 `Codex` 标签。手动添加与从 API 拉取的模型进入同一列表，使用相同的推荐规则。

| 模型行 | 初次显示 | 点击后的草稿 |
| --- | --- | --- |
| `codex/gpt-6.2-astra` | `推荐 Codex` | `Codex`，推荐档位上限 `max` |
| `codex/gpt-5.3-codex` | `推荐 Codex` | `Codex`，推荐档位上限 `xhigh` |
| `codex/新别名` | `推荐 Codex` | `Codex`，上限待确认，先用「自动」 |
| `chatgpt-api/gpt-6.2-astra` | `＋ 标签` | 由用户按该入口的实际能力选择 |
| `deepseek-v4.1-flash` | `＋ 标签` | 初始为空 |

点击「推荐 Codex」会把标签和推荐上限填入草稿。点击「＋ 标签」可以手动选择，适合模型名和网关别名无法体现实际能力的情况。点开已选标签可修改上限或移除标签。用户点现有的「验证并保存」后生效，同一入口用于新建和编辑。

保存后，聊天模型菜单由运行时返回的能力决定。Codex 档位包含「自动」和已确认上限以内的档位。上限为 `max` 时展示低、中、高、超高、最高。上限为 `xhigh` 时展示到超高。上限待确认时先显示「自动」，方便用户稍后补充。标签的外观沿用当前模型菜单的紫色样式和紧凑尺寸。

## 前端推荐规则

1. **优先读取模型目录中的明确能力声明。** 当网关给出模型系列及支持档位，推荐相应标签与上限，列表内可查看「网关目录声明」这一依据。目录只给模型 ID 时继续使用后两条。
2. **按明确的 Codex 路由或型号推荐。** `codex/` 路由可以推荐 Codex。已核实的明确型号可以附带上限。当前使用的 Astra 和 Sol 推荐到 `max`，5.2 和 5.3 Codex 推荐到 `xhigh`。仅能确认路由时，推荐标签并将上限留为待确认。
3. **遇到相同后缀或无可靠信号时保留手动入口。** 其他网关池里出现相同的型号后缀，可能使用不同的能力或映射。只看见 `gpt` 或同名后缀时，展示「＋ 标签」。

推荐始终是待采纳项。它可以随目录更新和模型别名变化重新计算，已保存的标签与上限由用户编辑。打开已有配置时，旧版靠名称识别的模型也能看到对应推荐。

## 从 Codex 切到其他模型

当前请求按它开始时的模型执行。切换生效后的下一次模型请求，使用目标 API 配置、模型和标签重新选择参数并整理发往上游的消息。

| 内容 | 下一次请求的处理 |
| --- | --- |
| 思考强度 | 从 Codex 切到未打标模型时，继承的档位回到「自动」，包括 `high`。若用户在切换时明确选了目标模型的合法档位，按新选择执行。两个 Codex 模型之间可沿用双方支持的档位，超过目标上限时回到「自动」。 |
| 请求参数 | 由目标模型和目标协议重新构造。`reasoning.effort`、`output_config.effort` 和续传引用等字段按目标规则生成。 |
| 聊天正文和工具记录 | 复制可携带的用户消息、回答正文和成对的工具调用及结果，转换为目标协议格式。 |
| 协议专用历史 | 仅在来源和目标兼容时附带。跨模型或跨端点时，过滤源模型专用的摘要块、加密思考、签名、响应和输出项引用，以及目标协议无法表示的服务端工具项。目标模型若需要自己的推理字段，按自身契约提供。 |

过滤仅发生在发往模型的临时副本上。用户在聊天里仍可回看原始答复、思考摘要和工具结果。档位因切换回到「自动」时，模型菜单同步角标，并在当前会话提示一次「思考强度已恢复为自动」。

## 落地与验收

- 设置保存以 `API 配置 ID + 模型 ID` 定位标签和可选上限。推荐结果单独计算。模型菜单、档位校验和请求构造统一读取已保存能力。
- 打标前 `codex/gpt-6.2-astra` 使用通用规则。采纳标签并保存后菜单出现超高与最高，刷新和重启后仍保留。相同 ID 在另一份 API 配置中可单独保持空标签。
- 用一个型号名中没有 `codex` 的模型验证手动打标也能启用同一套行为。用新别名验证推荐不会擅自填入未经确认的上限。
- 在同一会话先用 Codex 生成摘要和工具记录，再切换到普通模型。验证新请求移除了源模型专用字段，工具调用和结果依然配对，聊天历史仍可查看。覆盖同一端点换模型、跨端点和跨协议切换。
- 复用现有 API 配置表单和聊天模型菜单。保存时的连接探针验证当前配置可用，另用目标协议的真实 SDK 请求体对照切换结果。
