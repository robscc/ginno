## P2-6：TEAM.md 要不要进知识库索引？

### 结论：**不进。刻意隔离是对的，维持现状。**

### 依据（代码事实，非推测）

两者**已经在同一注入层**，但语义刻意不同：

| | TEAM.md / 实例 notes | 知识库（wiki） |
|---|---|---|
| 注入点 | `graph_prompts.build_turn_context` → `wrap_context_section("team_context", …)` | 同一函数 → `wrap_context_section("injected_wiki", …)` |
| 触发条件 | **无条件**：只要是团队成员会话就注入（`teams/memory.py:turn_context`） | **按 query 检索**：`build_wiki_context(query)` 命中才注入 |
| 内容性质 | 用户定下的**约定/准则**（「所有产出必须附证据」） | 可检索的**事实/知识** |
| 长度控制 | 硬上限裁剪（`TEAM_MD_MAX_CHARS` / `MEMBER_NOTES_MAX_CHARS`） | 检索相关性排序 + 条数上限 |
| 权威级别 | 视为本团队工作准则（注入文案明写 "treat as instructions"） | 参考资料，需引用溯源 |

**三条理由**：

1. **约定必须无条件生效，不能靠检索命中。** 「报完成必须附证据」这种纪律，
   如果进 KB 走 query 检索，那么用户问「今天天气如何」时它就不注入了——
   纪律恰好在最需要它的时候缺席。这是语义错配，不是性能优化。

2. **权威级别不同，混在一起会稀释。** TEAM.md 是命令式准则，wiki 是陈述式
   知识。放进同一个检索池，模型无法区分「必须遵守」与「可以参考」，
   而 KB 的引用规范（`<ginno_citations>`）还会要求给约定标来源——荒谬。

3. **隔离已经生效且零成本。** 非团队会话 `turn_context` 返回空串，
   团队记忆不会泄漏进无关会话（已有 turn 级测试断言：
   `test_team_memory_injection.py::test_non_team_session_gets_no_team_memory`）。
   进 KB 反而要新增「按团队过滤检索结果」的隔离逻辑，是**增加**复杂度。

### 什么情况下复议

- 用户明确要求「把团队沉淀的经验变成可跨团队检索的知识」——那是**另一个功能**
  （团队经验 → KB 的显式导出动作，类似 Instincts 的 evolve 成 SKILL.md），
  不是把 TEAM.md 本身塞进索引。
- TEAM.md 长到硬上限裁剪开始丢内容（当前上限见 `teams/memory.py`），
  说明它被当知识库用了——那时该引导用户拆分，而不是改注入机制。

## P2-7：goals 要不要接 team？

### 结论：**本轮不做，但阻塞已解除，可随时开工。**

### 依据

- goals 存储是 **per-project、按 session_id 键**（`goals/store.py:1,7`）。
  团队主会话与成员实例都是普通 session，**结构上天然兼容**——
  不需要改 goals 存储就能把 goal 挂到某个会话上。
- backlog 原判断「与团队模型正交」仍然成立：goal 驱动的是**单会话持续目标**，
  团队是「广场 + 常驻成员」的协作面。二者不是同一层的东西。
- **但原依赖已解除**：backlog 写「若做形态是『goal 挂 leader 会话、由 Lead
  分派』，依赖 P0-2」。P0-2 本轮已修（领队实例现在真能拿到
  `list_members`/`deliver_to_member`/`assign_task` 三件工具），
  所以这个形态**现在技术上可行**，不再是空转。

### 建议形态（若将来做）

goal 挂**领队实例会话**（不是广场主会话——广场永不自跑 turn）：
1. 领队在 goal 驱动下持续思考「下一步派谁做什么」
2. 用 `assign_task` 分派给成员
3. 成员回帖 → 领队判断是否达成 goal → 未达成继续派

这实际上是「自主运转的团队」，与编排提案的 B4（事件/定时驱动）同一方向。

### 为什么本轮不做

- 它是**新能力**不是缺陷，混进「修 backlog」会让交付边界模糊。
- 需要产品决策：goal 的预算/熔断如何与团队并发闸叠加？领队在 goal 驱动下
  反复分派，成本护栏在哪？这些在编排提案 D2（预算与熔断）里还没落地。
- 已有 P2-1（schedule 驱动团队）覆盖了「定时让团队干活」这个更常见的需求，
  goal 驱动的边际价值待验证。

### 复议条件

编排提案的 **D2 预算熔断**落地后，再评估 goal 驱动——否则自主分派没有成本护栏。
